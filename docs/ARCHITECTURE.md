# Архитектура

> Этап 1 в работе. Каркас, настройки и SQLite реализованы; проверка GUI и замер сетевого трафика остаются открытыми.

## Реализованный каркас

- Wails v3.1.0, Svelte и TypeScript. Команды запуска и сборки: `wails3 dev`, `wails3 build`.
- `main.go` открывает настройки, готовит папку данных, открывает SQLite и регистрирует `internal/app.SettingsService` для вызовов из фронтенда.
- `internal/settings/` хранит папку данных и язык (`auto`, `ru`, `en`) в `<user config dir>/Pitch/settings.json`. Запись идёт через временный файл с заменой. По умолчанию данные находятся в `<home>/Pitch`.
- `internal/app/` предоставляет чтение и сохранение настроек и выбор папки. Смена папки применяется после перезапуска; существующие данные автоматически не переносятся.
- `internal/storage/` открывает `pitch.sqlite` через `modernc.org/sqlite`, включает WAL, внешние ключи и таймаут блокировки. SQL-миграции из `internal/storage/migrations/` встроены в приложение, применяются транзакционно; более новая версия схемы отклоняется.
- `frontend/src/screens/Settings.svelte` — текущий экран приложения: папка данных и язык. Строки интерфейса находятся в `frontend/src/i18n/`. Остальные экраны ниже пока запланированы.
- `startuperror*.go` обрабатывают ошибки до создания основного окна: на Windows используется нативное окно RU/EN, на остальных платформах пока есть только вывод в лог.
- CSP разрешает подключения только к origin приложения, необходимые для Wails IPC. `webview2.go` ограничивает разрешения и фоновые службы WebView2; профиль браузера находится в `<data>/webview/`. Тест `internal/nonet/` проверяет прямые сетевые импорты в `internal/`. Эти меры не заменяют замер трафика WebView2, который ещё не завершён.

## Слои

```
┌──────────────────────────────────────────┐
│ Фронтенд (WebView): интерфейс, камера,   │
│ MediaRecorder, таймеры, плеер            │
└───────────────┬──────────────────────────┘
                │ вызовы методов Wails (IPC)
┌───────────────▼──────────────────────────┐
│ Go-бэкенд: проекты, попытки, настройки,  │
│ темы, работа с файлами, запуск           │
│ LibreOffice                              │
└───────────────┬──────────────────────────┘
                │
┌───────────────▼──────────────────────────┐
│ Хранилище: SQLite + папка с видео,       │
│ превью и слайдами                        │
└──────────────────────────────────────────┘
```

Тяжёлую работу (захват, кодирование, воспроизведение видео) выполняет WebView и системные кодеки. Go отвечает за данные и файлы.

## Хранение данных

Папка данных настраивается пользователем. Сейчас создаются SQLite и профиль WebView2; видео, превью и слайды ниже — планируемая структура:

```
<data>/
├── pitch.sqlite
├── webview/
├── videos/<attempt_id>.webm
├── thumbs/<attempt_id>.jpg
└── slides/<project_id>/<version>/<n>.png
```

## Схема БД

Начальная схема реализована в `internal/storage/migrations/0001_init.sql`, учёт миграций — в `schema_migrations`. Репозитории и пользовательские сценарии работы с проектами и попытками пока не реализованы.

- `projects`: id, name, type (`pptx` | `free`), pptx_path, created_at
- `project_versions`: id, project_id, file_hash, version_number, created_at
- `attempts`: id, project_id, version_id, video_path, thumb_path, duration_sec, topic, scores (json), note, created_at
- `slide_timings`: attempt_id, slide_index, start_sec, end_sec

Таблицы `topic_sets` и `topics` запланированы для этапа импровизации. Настройки сейчас хранятся в JSON, таблицы `settings` нет.

## Ключевые потоки

**Запись попытки.** Фронтенд включает камеру, `MediaRecorder` пишет чанки, по завершении видео передаётся в Go и сохраняется файлом. Таймлайн слайдов фронтенд накапливает в памяти и отправляет вместе с видео. Камера освобождается при выходе с экрана.

**Версии презентации.** При открытии проекта Go считает хэш pptx. Если он отличается от последней версии, создаётся новая запись в `project_versions`, слайды переконвертируются.

**Конвертация слайдов.** Go проверяет наличие LibreOffice, запускает его в headless-режиме, результат кэшируется по хэшу. Если LibreOffice нет, приложение предлагает загрузить PDF.

## Приватность и сеть

Прикладной код не должен выполнять сетевые запросы. CSP и конфигурация WebView2 ограничивают сеть; все ресурсы интерфейса включены в сборку. Отсутствие фонового трафика браузера необходимо подтвердить отдельным замером.

Для разработки на Windows добавлен `scripts/netwatch.ps1`: он наблюдает TCP/UDP у заданного процесса и его текущих потомков. Порядок и ограничения проверки описаны в [NETWORK-CHECK.md](NETWORK-CHECK.md). Скрипт не входит в приложение.
