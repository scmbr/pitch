# Архитектура

> Реализованы каркас и экран тренировки. Настройки и запись проверены на настоящем WebView2 на Windows. Проверка записи использует тестовые устройства; физические камеры и другие ОС проверяются перед релизом.

## Реализованный каркас

- Wails v3.1.0, Svelte и TypeScript. Команды запуска и сборки: `wails3 dev`, `wails3 build`.
- `main.go` открывает настройки, готовит папку данных, открывает SQLite и регистрирует `internal/app.SettingsService` для вызовов из фронтенда.
- `internal/settings/` хранит папку данных и язык (`auto`, `ru`, `en`) в `<user config dir>/Pitch/settings.json`. Запись идёт через временный файл с заменой. По умолчанию данные находятся в `<home>/Pitch`.
- `internal/app/` предоставляет чтение и сохранение настроек и выбор папки. Смена папки применяется после перезапуска; существующие данные автоматически не переносятся.
- `internal/storage/` открывает `pitch.sqlite` через `modernc.org/sqlite`, включает WAL, внешние ключи и таймаут блокировки. SQL-миграции из `internal/storage/migrations/` встроены в приложение, применяются транзакционно; более новая версия схемы отклоняется.
- `frontend/src/App.svelte` переключает настройки и тренировку. `Settings.svelte` управляет папкой данных и языком, `Training.svelte` — подготовкой, выступлением и записью. Строки интерфейса находятся в `frontend/src/i18n/`.
- `frontend/src/lib/timer.js` считает время по монотонным отметкам, сохраняет превышение границы подготовки, исключает паузы и поддерживает овертайм. Тесты запускаются встроенным тестовым раннером Node.js.
- `frontend/src/lib/recorder.ts` запрашивает 1280×720, 15 кадров/с и микрофон по нажатию старта. MediaRecorder формирует WebM; очередь отправляет чанки до 256 КиБ, при накоплении более 32 МиБ запись останавливается с ошибкой. Завершение, отмена и уничтожение экрана освобождают все треки.
- `internal/app.RecordingService` принимает чанки по случайному идентификатору единственной активной записи. Пути не принимаются из UI. Данные пишутся в `videos/<token>.partial`, после flush/close файл переименовывается в `<token>.webm` и регистрируется в истории. Ошибка регистрации возвращает файл в незавершённое состояние для очистки. Отмена и штатное закрытие удаляют незавершённый файл.
- `internal/attempts.Store` связывает видео с проектом свободной тренировки, хранит длительность, три оценки и заметку. Фронтенд один раз создаёт JPEG-превью перед остановкой камеры. Лимит учитывает видео и превью; при сохранении новой попытки старейшие удаляются только при включённом `autoDelete`. Сам новый файл ещё временно занимает место сверх лимита во время записи.
- Удаление сохраняет `attempts.deleting=1`, удаляет медиафайлы, затем строку БД. При занятом файле остаётся строка с возможностью повтора. При запуске выполняется повтор удаления и импорт завершённых WebM без строки БД (для восстановления после сбоя и записей предыдущей версии).
- Корневой `media.go` обслуживает только `/media/<token>.webm` и `.jpg` из папки приложения, поддерживает HTTP Range для перемотки. Это обработчик локального origin Wails без отдельного сервера или HTTP-клиента. Файловые пути через API воспроизведения не принимаются.
- `History.svelte` показывает попытки, плеер, оценки, заметки и настройки лимита. Удаление требует подтверждения внутри приложения и предварительно освобождает плеер.
- `startuperror*.go` обрабатывают ошибки до создания основного окна: на Windows используется системное окно, на macOS/Linux — нативный диалог Wails в отдельном цикле событий без WebView. Используется сохранённый RU/EN либо язык системы. После закрытия ошибки приложение завершается.
- CSP разрешает подключения только к origin приложения, необходимые для Wails IPC. `webview2.go` ограничивает разрешения и фоновые службы WebView2, отклоняет внешние DNS-имена и отключает системный прокси; профиль браузера находится в `<data>/webview/`. Тест `internal/nonet/` проверяет прямые сетевые импорты в `internal/`. Сравнительный замер на Windows описан в [NETWORK-CHECK.md](NETWORK-CHECK.md).

## Слои

```
┌──────────────────────────────────────────┐
│ Фронтенд (WebView): интерфейс, камера,   │
│ MediaRecorder, таймеры, плеер            │
└───────────────┬──────────────────────────┘
                │ вызовы методов Wails (IPC)
┌───────────────▼──────────────────────────┐
│ Go-бэкенд: проекты, попытки, настройки,  │
│ темы, работа с файлами, запуск           │
│ LibreOffice                              │
└───────────────┬──────────────────────────┘
                │
┌───────────────▼──────────────────────────┐
│ Хранилище: SQLite + папка с видео,       │
│ превью и слайдами                        │
└──────────────────────────────────────────┘
```

Тяжёлую работу (захват, кодирование, воспроизведение видео) выполняет WebView и системные кодеки. Go отвечает за данные и файлы.

## Планируемая структура папок

```
/
├── main.go                 # точка входа Wails
├── internal/
│   ├── app/                # методы, доступные фронтенду
│   ├── storage/            # SQLite, миграции, репозитории
│   │   └── migrations/    # встроенные SQL-миграции
│   ├── projects/           # проекты, версии по хэшу
│   ├── attempts/           # попытки, таймлайн слайдов
│   ├── topics/             # наборы тем, импорт
│   ├── slides/             # конвертация pptx/PDF в картинки
│   └── settings/           # настройки и их хранение
├── frontend/
│   └── src/
│       ├── screens/        # тренировка, история, проект, сравнение, настройки
│       ├── components/
│       ├── lib/            # таймеры, запись, горячие клавиши
│       └── i18n/           # ru, en
└── docs/
```

Сейчас существуют `internal/app`, `internal/settings`, `internal/storage`, `internal/nonet` и экран настроек. Остальные предметные модули добавляются в следующих этапах.

## Хранение данных

Папка данных настраивается пользователем. Сейчас создаются SQLite и профиль WebView2; видео, превью и слайды ниже — планируемая структура:

```
<data>/
├── pitch.sqlite
├── webview/
├── videos/<attempt_id>.webm
├── thumbs/<attempt_id>.jpg
└── slides/<project_id>/<version>/<n>.png
```

## Схема БД

Начальная схема реализована в `internal/storage/migrations/0001_init.sql`, учёт миграций — в `schema_migrations`. Миграция 0002 добавляет намерение удаления и уникальность видеофайла. Реализован репозиторий попыток; проекты презентаций добавляются следующим этапом.

- `projects`: id, name, type (`pptx` | `free`), pptx_path, created_at
- `project_versions`: id, project_id, file_hash, version_number, created_at
- `attempts`: id, project_id, version_id, video_path, thumb_path, duration_sec, topic, scores (json), note, created_at
- `slide_timings`: attempt_id, slide_index, start_sec, end_sec

Таблицы `topic_sets` и `topics` запланированы для этапа импровизации. Настройки сейчас хранятся в JSON, таблицы `settings` нет.

## Планируемые предметные потоки

**Запись попытки.** Реализованы включение камеры по действию пользователя, порционная передача MediaRecorder в Go и сохранение WebM. Подготовка показывает превью, запись начинается с выступления; пауза останавливает и таймер, и MediaRecorder. Таймлайн слайдов и связь с БД добавляются в следующих этапах. Камера освобождается при выходе с экрана.

**Версии презентации.** При открытии проекта Go считает хэш pptx. Если он отличается от последней версии, создаётся новая запись в `project_versions`, слайды переконвертируются.

**Конвертация слайдов.** Go проверяет наличие LibreOffice, запускает его в headless-режиме, результат кэшируется по хэшу. Если LibreOffice нет, приложение предлагает загрузить PDF.

## Приватность и сеть

Прикладной код не должен выполнять сетевые запросы. CSP и конфигурация WebView2 ограничивают сеть; все ресурсы интерфейса включены в сборку. В сценарии настроек на WebView2 156.0.4314.58 внешнего трафика рабочей конфигурации не обнаружено; при обновлении браузера и добавлении медиасценариев проверка повторяется.

Для разработки на Windows добавлен `scripts/netwatch.ps1`: он наблюдает TCP/UDP у заданного процесса и его текущих потомков. Порядок и ограничения проверки описаны в [NETWORK-CHECK.md](NETWORK-CHECK.md). Скрипт не входит в приложение.
