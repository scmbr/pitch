# Проверка сети на Windows

`scripts/netwatch.ps1` — инструмент разработки для наблюдения за TCP-соединениями и UDP-сокетами Pitch и его текущих дочерних процессов, включая WebView2. Он не входит в приложение, не запускает его и не меняет брандмауэр.

Собери приложение командой `wails3 build`, запусти `bin/pitch.exe`, затем в другом PowerShell:

```powershell
Get-Process pitch | Select-Object Id, StartTime
./scripts/netwatch.ps1 -ProcessId 1234 -DurationSeconds 30
```

Подставь PID нужного экземпляра. При отказе в доступе повтори наблюдение из PowerShell с правами администратора. JSON сохраняется в игнорируемую Git папку `data/network/`; существующие отчёты не перезаписываются. Отчёт содержит имена и PID процессов, локальные и удалённые адреса TCP и локальные порты UDP. Не добавляй результаты с локальными данными в Git.

Во время наблюдения открой настройки, смени язык и сохрани настройки. После появления экрана тренировки отдельно проверь камеру, запись, воспроизведение и выход с экрана. Скрипт останавливается по таймеру или при завершении исходного процесса. Ошибка чтения таблиц соединений сохраняется в неполный отчёт и завершает скрипт с ошибкой.

Для сравнения ограничений WebView2 используй одинаковую сборку и сценарий с отдельными чистыми папками данных: без ограничивающих флагов, с текущими флагами и отдельно с `--host-resolver-rules`. Флаги меняются только в локальной диагностической сборке, а не в рабочей конфигурации приложения. Зафиксируй версию WebView2, вариант флагов, длительность, сценарий и результат каждого запуска.

Опрос таблиц соединений может пропустить короткие соединения и процессы. Интервал задаёт паузу между опросами: сами запросы Windows требуют дополнительного времени, особенно первый. Поля `TimestampUtc` и `FinishedAtUtc` каждого замера показывают время начала и завершения запросов. У UDP-сокетов здесь нет адреса назначения, а DNS может обслуживаться системным процессом. Пустой список не доказывает отсутствие трафика. Для завершения проверки нужны также журнал брандмауэра или захват пакетов и сопоставление с деревом процессов. Скрипт не включает и не меняет системное журналирование.

Проверка логики скрипта без доступа к сети и без дополнительных зависимостей:

```powershell
./scripts/netwatch.test.ps1
```

## Результат проверки каркаса, 2026-11-07

На Windows 10 с WebView2 156.0.4314.58 проверены три диагностические production-сборки с отдельными чистыми профилями. Go overlay добавлял NetLog и проверку настоящего UI через нативный мост; в обычной сборке этих дополнений нет. Отладочный порт не использовался. В каждом запуске выполнены чтение настроек, RU/EN, отклонение относительного пути, сохранение папки и проверка CSP.

| Конфигурация | Замеры `netwatch` за 30 с | Внешние TCP-адреса в NetLog | События `UDP_BYTES_SENT` | События TCPIP дерева процессов |
| --- | ---: | ---: | ---: | ---: |
| Без ограничивающих флагов | 37 | 1, HTTPS | 14 | 320 |
| Исходные флаги подавления фоновых служб | 37 | 0 | 0 | 176 |
| Флаги + запрет DNS и системного прокси | 36 | 0 | 0 | 128 |

ETW-сессия провайдеров `Microsoft-Windows-WFP` и `Microsoft-Windows-TCPIP` запущена через `logman` с правами Performance Log Users и остановлена после сценариев. Обработано 85 313 событий без потерь. Для атрибуции TCPIP использовался PID владельца из данных события, если он присутствует: PID исполняющего потока в заголовке может принадлежать чужой операции. События WFP без AppId не приписывались приложению. TCPIP подтвердил внешний HTTPS-адрес только у контрольной сборки без флагов; у двух ограниченных сборок — только loopback.

NetLog также содержит локальную проверку IPv6-маршрута через `UDP_CONNECT`; у ограниченных вариантов нет `UDP_BYTES_SENT`. Создание UDP-сокета само по себе не означает отправку пакета. Loopback-обращения к origin Wails учитывались отдельно от внешней сети.

В рабочую конфигурацию включены `--host-resolver-rules` с отклонением внешних имён и исключениями для Wails/loopback, а также `--no-proxy-server`. Последний не даёт системному прокси разрешать имена вместо браузера. Синтаксис правила сверялся с [исходниками Chromium](https://chromium.googlesource.com/chromium/src/+/refs/heads/main/net/dns/mapped_host_resolver.cc); диагностический NetLog описан в [документации WebView2](https://learn.microsoft.com/en-us/microsoft-edge/webview2/concepts/webview-features-flags).

Это результат конкретного сценария и версии WebView2. После обновления браузера или добавления записи/проигрывания замер нужно повторить. Сырые трассы и профили остаются локально в `data/`.

## Медиасценарий и идентичность процессов

Диагностический запуск с настоящим WebView2, тестовыми камерой/микрофоном и NetLog:

```powershell
./scripts/check-settings.ps1 -Scenario projects -NetworkLog
node scripts/summarize-netlog.mjs data/ui-<run>/home/Pitch/netlog.json
./scripts/process-identity.test.ps1
```

Сценарий импортирует презентацию, использует PDF при отсутствии LibreOffice, растеризует слайды, записывает две попытки, проверяет воспроизведение и сравнение. После освобождения медиаресурсов приложение остаётся открытым ещё 30 секунд для наблюдения за отложенной активностью. Рядом с профилем сохраняются `<phase>-process.json` и `<phase>-sockets.json`; у сценария настроек отдельные отчёты для `edit` и `restart`. Наблюдатель ограничен 150 секундами и останавливается при выходе корневого процесса. Это не включает системный ETW-захват: его необходимо запустить отдельно до приложения и остановить после его завершения.

`netwatch` сохраняет `ProcessStartKey` строкой, чтобы не терять точность 64-битного значения. Ключ читается с проверкой времени создания; при недоступности метаданных поле пустое. Для строгой атрибуции TCPIP нужны PID владельца из данных события и совпадающий ключ запуска. Совпадения только PID или PID потока в заголовке недостаточно; события без подтверждённого владельца остаются неатрибутированными.

Анализатор NetLog считает попытки TCP с адресом, отдельно отмечает внешние адреса и `UDP_BYTES_SENT`, не публикуя сами адреса. При их наличии CLI возвращает код 1. Успешный результат относится только к Chromium и требует сопоставления с системной трассой.

Повторный замер 2026-11-07: сценарий прошёл, ETW WFP/TCPIP/WinHTTP собрал 81 020 событий за 68 секунд без потерь, последовательный файл не достиг установленного ограничения. По подтверждённым PID/ключам запуска внешних TCP-адресов не найдено. NetLog: 296 событий, 6 локальных попыток TCP, 0 внешних, 0 `UDP_BYTES_SENT`, 2 события `UDP_CONNECT`.

**Релизная проверка сети остаётся открытой.** В более раннем захвате обнаружены два успешных внешних HTTPS-соединения по PID, который наблюдался у WebView2. В том запуске ключи процессов ещё не сохранялись; повторные запуски находку не воспроизвели, но это не объясняет её происхождение. Нельзя объявлять её ни доказанной передачей Pitch, ни доказанным повторным использованием PID. Также ещё требуются установленный LibreOffice и физические устройства. Захваты с потерями событий или возможным переполнением кольцевого файла не используются как доказательство отсутствия сети.
