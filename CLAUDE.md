# Pitch: инструкции для Claude Code

Офлайн-десктопное приложение (Go + Wails) для тренировки выступлений.
Главная ценность: история попыток, привязанная к презентации (pptx), и сравнение попыток.

## Источники правды

- Что строим: @docs/private/SPEC.md (локальный файл, может отсутствовать; тогда опирайся на docs/private/TODO.md и ARCHITECTURE.md)
- Что делаем сейчас: @docs/private/TODO.md (локальный файл, может отсутствовать)
- Как устроено: @docs/ARCHITECTURE.md
- Почему приняты решения: `docs/private/decisions/` (локальная папка, может отсутствовать)

Всё внутри `docs/private/` локальное: в git не попадает и может отсутствовать. Не коммить эти файлы.

Читай эти файлы в начале работы над этапом, а не держи их в голове.

## Стек

- Бэкенд: Go + Wails (перед стартом проверь актуальную стабильную версию)
- Фронтенд: Svelte или vanilla TS, без тяжёлых фреймворков, без CDN
- Запись: getUserMedia + MediaRecorder, 720p, WebM
- Хранилище: SQLite через modernc.org/sqlite (без CGO) + видеофайлы в папке пользователя
- pptx: конвертация через LibreOffice headless, если установлен; запасной путь: PDF от пользователя

## Команды

Уточни и обнови этот раздел после этапа 1.

```
wails dev            # разработка
wails build          # сборка
go test ./...        # тесты бэкенда
golangci-lint run    # линтер
```

## Жёсткие ограничения

- **Никакой сети.** Ни запросов, ни телеметрии, ни автообновлений, ни внешних шрифтов и CDN. Все ресурсы вшиты в сборку. Не добавляй зависимости, которые ходят в сеть.
- **Лёгкость.** Нет фоновых процессов и автозапуска. Камера включается только на экране тренировки и освобождается сразу после него.
- **Приватность.** Данные только локально. Удаление попытки удаляет файл с диска, а не только запись в БД. Экспорт только по кнопке.
- **Клавиатура.** Всё основное доступно с клавиатуры, горячие клавиши переназначаемые.

## Правила кода

- Маленькие модули, понятные имена. Комментарии только там, где неочевидно «почему».
- Ошибки камеры, диска и LibreOffice обрабатывай с понятным пользователю сообщением.
- Тесты для таймеров, версионирования по хэшу файла и работы с БД.
- Новую зависимость добавляй только при необходимости и объясняй, зачем она нужна.
- Все строки интерфейса через локализацию (русский и английский), не хардкодь текст.
- Секреты, пути к личным папкам и личные заметки в репозиторий не попадают.

## Git и PR

- Формат коммитов: Conventional Commits на английском (`feat:`, `fix:`, `docs:`, `refactor:`, `test:`, `chore:`).
- Одна задача или один этап на ветку и PR. Ветки: `feat/...`, `fix/...`, `docs/...`.
- Мелкие коммиты. Перед коммитом запускай тесты и линтер.
- Не добавляй `Co-Authored-By` и любые подписи об авторстве ИИ в коммиты и описания PR.
- Не упоминай в коммитах, PR и публичных файлах монетизацию, конкурентов и планы вне MVP.
- Не делай `git push` без моей команды. Не используй `--force` и `reset --hard`.

## Конец каждого этапа

1. Отметь чекбоксы в `docs/private/TODO.md` и обнови строку «Текущий этап».
2. Добавь строку в `CHANGELOG.md` (раздел Unreleased).
3. Обнови `docs/ARCHITECTURE.md`, если менялась структура.
4. Если принято нетривиальное решение, добавь запись в `docs/private/decisions/` (локально, без коммита).
