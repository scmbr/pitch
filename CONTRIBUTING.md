# Contributing

Спасибо за интерес к проекту. Pitch полностью офлайн: любые изменения, добавляющие сетевые запросы, телеметрию или внешние ресурсы, не принимаются.

## Быстрый старт

1. Установи Go, Node.js, совместимый с зависимостями фронтенда (для ветки 22 — не ниже 22.12), и Wails (см. документацию Wails для своей ОС).
2. `git clone` и `wails3 dev` (проект использует Wails v3.1.0).
3. Сборка приложения: `wails3 build`.
4. Тесты: `go test ./...`, линтер: `golangci-lint run`.
5. Проверка фронтенда: из `frontend/` запусти `npm run check`, `npm test` и `npm run build`. Полная сборка приложения генерирует необходимые Wails bindings.

Для работы с pptx желателен установленный LibreOffice, но приложение должно работать и без него.

Наблюдение за сетевыми соединениями Windows: [инструкция](docs/NETWORK-CHECK.md). Проверка скрипта без сетевых запросов: `./scripts/netwatch.test.ps1` в PowerShell.

Проверка настоящего экрана настроек и перезапуска на Windows: `./scripts/check-settings.ps1`. Сначала собери фронтенд и bindings через `wails3 build`. Проверка использует отдельную сборку через Go overlay и изолированные настройки в `data/`; пользовательские настройки не меняются, отладочный порт не открывается.

Проверка тренировки: `./scripts/check-settings.ps1 -Scenario training`. Только диагностическая сборка использует тестовые камеру и микрофон WebView2. Проверяются 720p, пауза, овертайм, сохранение WebM, отмена и освобождение медиапотоков при навигации. Работа с физическими устройствами проверяется отдельно перед релизом.

## Ветки

- `feat/короткое-описание` для новых функций
- `fix/короткое-описание` для исправлений
- `docs/короткое-описание` для документации

Прямые пуши в `main` закрыты, всё идёт через pull request.

## Коммиты

[Conventional Commits](https://www.conventionalcommits.org/), сообщения на английском:

```
feat: add slide timeline recording
fix: release camera when leaving the training screen
docs: update architecture overview
```

Мелкие коммиты лучше больших. Перед коммитом запусти тесты и линтер.

## Pull request

- Одна задача на PR.
- В описании: что изменено и зачем, как проверить.
- Если менялась структура, обнови `docs/ARCHITECTURE.md`.
- Пользовательские изменения отражай в `CHANGELOG.md`.

## Принципы проекта

- **Офлайн.** Никакой сети.
- **Лёгкость.** Никаких фоновых процессов, камера включается только на экране тренировки.
- **Приватность.** Данные пользователя остаются у него. Удаление означает удаление файла с диска.
- **Новые зависимости** добавляются только при необходимости, с объяснением в PR.

## Новые наборы тем

Темы пишутся самостоятельно, без копирования из книг и чужих сайтов, по одной на строку.
