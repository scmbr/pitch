# Pitch — инструкции для AI coding agents

Офлайн-десктопное приложение (Go + Wails) для тренировки выступлений.

Главная ценность: история попыток, привязанная к презентации (`.pptx`), и сравнение попыток.

## Источники правды

Перед началом нового этапа или крупной задачи прочитай актуальную документацию:

1. `docs/private/SPEC.md` — что строим. Если файла нет, ориентируйся на TODO и архитектуру.
2. `docs/private/TODO.md` — текущий этап и задачи.
3. `docs/ARCHITECTURE.md` — архитектура приложения.
4. `docs/private/decisions/` — история архитектурных решений, если каталог существует.

Не считай ранее прочитанные документы актуальными без повторной проверки.

Всё внутри `docs/private/` — локальная документация, которая может отсутствовать и не должна попадать в Git. Не добавляй эти файлы принудительно и не коммить их.

Если документация противоречит существующему коду, сообщи о расхождении и уточни предполагаемое изменение, прежде чем менять архитектуру.

## Технологический стек

- Бэкенд: Go + Wails. Перед первоначальной настройкой проверь актуальную стабильную версию, если доступна сеть.
- Фронтенд: Svelte или vanilla TypeScript, без тяжёлых фреймворков.
- Запись: `getUserMedia` + `MediaRecorder`, целевой формат — 720p WebM.
- Хранилище: SQLite через `modernc.org/sqlite` (без CGO), видеофайлы — в пользовательском каталоге данных приложения.
- Презентации: конвертация `.pptx` через LibreOffice headless, если установлен; альтернативный путь — PDF, предоставленный пользователем.

Не меняй утверждённый стек без обоснования и согласования.

## Команды

После первоначальной настройки проекта проверь команды и обнови этот раздел.

```bash
wails dev
wails build
go test ./...
golangci-lint run
```

Не утверждай, что тесты или сборка прошли успешно, если соответствующие команды не выполнялись.

## Жёсткие ограничения продукта

### Полностью офлайн

- Приложение не выполняет сетевые запросы.
- Никакой телеметрии, аналитики, автообновлений, CDN или внешних шрифтов.
- Все необходимые ресурсы включены в сборку.
- Не добавляй зависимости, которые требуют сетевого доступа во время работы приложения.
- Сетевой доступ при разработке допускается для установки зависимостей и проверки документации, но не должен приводить к сетевым функциям в готовом приложении.

### Производительность и ресурсы

- Никаких постоянных фоновых процессов или автозапуска.
- Камера и микрофон включаются только при необходимости для тренировки.
- После завершения тренировки освобождай медиапотоки и связанные ресурсы.

### Приватность и данные

- Все пользовательские данные хранятся локально.
- Удаление попытки должно удалять и запись из БД, и соответствующий видеофайл.
- Экспорт данных — только по явному действию пользователя.
- Не добавляй в Git секреты, абсолютные пути к личным каталогам и локальные заметки.

### Доступность

- Основные действия доступны с клавиатуры.
- Горячие клавиши должны поддерживать переназначение.

## Правила разработки

- Используй небольшие модули и понятные имена.
- Комментарии должны объяснять неочевидные причины решений, а не пересказывать код.
- Ошибки камеры, микрофона, диска и LibreOffice обрабатывай с понятными пользователю сообщениями.
- Пиши тесты для таймеров, версионирования презентаций по хэшу файла и работы с БД.
- Добавляй новые зависимости только при необходимости; объясняй их назначение.
- Все пользовательские строки проводи через локализацию (русский и английский). Не хардкодь текст интерфейса.
- Избегай несвязанных рефакторингов при выполнении конкретной задачи.
- Перед существенными архитектурными изменениями объясняй предлагаемый подход.

## Git и PR

- Используй Conventional Commits на английском: `feat:`, `fix:`, `docs:`, `refactor:`, `test:`, `chore:`.
- Для самостоятельной задачи используй отдельную ветку, если пользователь не указал иное.
- Имена веток: `feat/...`, `fix/...`, `docs/...`.
- Предпочитай небольшие логически завершённые коммиты.
- Перед коммитом запускай относящиеся к изменениям тесты и линтер. Если выполнить их невозможно, сообщи об этом.
- Не создавай коммиты и PR без явного запроса пользователя.
- Не выполняй `git push` без явной команды.
- Не используй `git push --force` и `git reset --hard`.
- Не добавляй `Co-Authored-By` и подписи об авторстве ИИ в коммиты и описания PR.
- Не упоминай в публичных файлах, коммитах и PR монетизацию, конкурентов и планы вне MVP.

## Завершение этапа

Когда этап действительно завершён:

1. Обнови чекбоксы и строку «Текущий этап» в `docs/private/TODO.md`, если файл существует.
2. Добавь запись в раздел `Unreleased` файла `CHANGELOG.md`.
3. Обнови `docs/ARCHITECTURE.md`, если изменилась архитектура.
4. Зафиксируй нетривиальные архитектурные решения в `docs/private/decisions/`, если локальный каталог существует.
5. Сообщи, что изменено, какие проверки выполнены и какие проблемы остались.

Не отмечай незавершённые задачи выполненными.

## Вне MVP

Не реализуй без отдельного запроса:

- Расшифровку речи.
- Анализ слов-паразитов.
- Графики прогресса.
- Шифрование видео.
- Облачную синхронизацию.
